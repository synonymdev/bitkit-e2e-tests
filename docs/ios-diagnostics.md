# iOS attempt diagnostics

The iOS WDIO hooks start recording before each setup hook and keep the same recording through the test body. A failed hook or body captures the original error, screenshot, page source, app process state, app-group log files, backend state/log tails and Namespace forwarding logs. Each operation is best-effort and bounded; collection errors do not replace the test failure. Android keeps its existing collector.

Before either reinstall helper removes the app, it copies only `group.bitkit/logs/*.log` into the current case's `before-reset-*` directory. This preserves app and LDK logs that would otherwise disappear during cleanup. No wallet databases, keychain data, certificates or full container inspection are collected. `ci_run_ios.sh` also collects attempt-end native/backend diagnostics before returning the test command's exit status. Normal retries retain earlier attempt directories.

Artifacts live under `artifacts/attempt-$ATTEMPT/<case>-<time>-<sequence>/`. Failed hook/body snapshots are in `failure/`; `SAVE_DIAGNOSTICS=true` also retains completed-case snapshots and recordings. `native-manifest.json` records unavailable probes and copied app log files. A missing screen/source is a collection failure, not evidence about the app's state. Per-case `collection-errors.log` retains failed probes, including Appium response details and recording cleanup errors. The local Appium HTTP probes have independent deadlines and do not inherit long WebDriver command retries.

The opt-in `test/diagnostics/probe.e2e.ts` is outside the default spec glob. Run it against a simulator app with `RECORD_VIDEO=true ./ci_run_ios.sh --spec ./test/diagnostics/probe.e2e.ts`. It deliberately fails one setup hook and one body; its nonzero exit is expected only for this probe. Verify separate failure manifests, screenshots, sources, recordings and nonempty app log manifests before relying on diagnostics from a product run. Do not include the probe in ordinary suite selection.
